## 核心权限差异总结

### 1. 评分记录权限

| 操作类型 | 普通鉴定员 | 管理员 | 超级管理员 |
|---------|-----------|--------|-----------|
| 查看自己的记录 | ✅ | ✅ | ✅ |
| 查看同牧场他人记录 | ✅（只读） | ✅ | ✅ |
| 查看其他牧场记录 | ❌ | ✅ | ✅ |
| 修改自己的记录 | ✅ | ✅ | ✅ |
| 修改他人的记录 | ❌ | ✅ | ✅ |
| 删除自己的记录 | ✅ | ✅ | ✅ |
| 删除他人的记录 | ❌ | ✅ | ✅ |

**关键点：**
- 普通鉴定员：只能改自己的，可以看同牧场其他人的（只读）
- 管理员/超级管理员：可以改所有人的（用于纠错和数据管理）

### 2. 牧场管理权限

| 操作类型 | 普通鉴定员 | 管理员 | 超级管理员 |
|---------|-----------|--------|-----------|
| 查看牧场列表 | 仅已分配 | 全部 | 全部 |
| 新建牧场 | ❌ | ✅ | ✅ |
| 修改牧场信息 | ❌ | ✅ | ✅ |
| 设置DHI编号 | ✅ | ✅ | ✅ |
| 搜索牧场 | ✅ | ✅ | ✅ |

**关键点：**
- 普通鉴定员：只能看到和使用被分配的牧场
- 管理员：可以创建牧场并管理所有牧场

### 3. 鉴定员-牧场匹配权限

| 查看匹配关系 | ✅ | ✅ | ✅ | 管理后台-牧场匹配Tab |
| 选择鉴定员 | ❌ | ✅ | ✅ | 下拉选择器 |
| 查看鉴定员可访问的牧场 | ✅ | ✅ | ✅ | 显示所有牧场+关联状态 |

| 关闭关联（移除权限） | ❌ | ✅ | ✅ | 关闭开关→取消关联 |
| 批量分配 | ❌ | ✅ | ✅ | 一次性操作多个牧场 |

**典型操作流程：**

**场景1：新鉴定员入职，分配工作牧场**
```
管理员操作：
1. 进入"设置" → "管理后台"
2. 切换到"牧场匹配"Tab
3. 选择新鉴定员（如：张三/A001）

```

**场景2：鉴定员离职或换岗，移除牧场权限**
```
管理员操作：
1. 进入"管理后台" → "牧场匹配"
2. 选择该鉴定员
3. 关闭所有牧场的开关
4. 系统取消所有关联

鉴定员体验：
1. 进入"选择牧场"页面
2. 显示"暂无可用牧场"
3. 无法进行评分工作
```

## 权限继承关系

```
超级管理员 (super_admin)
    ↓ 包含
管理员 (admin)
    ↓ 包含
普通鉴定员 (appraiser)
```

**说明：**
- 超级管理员拥有管理员的所有权限 + 角色管理权限
- 管理员拥有普通鉴定员的所有权限 + 牧场管理 + 数据管理权限
- 每个上级角色都是下级角色的超集

## 权限判断代码示例

### 1. 检查是否可以编辑记录

```javascript
function canEditRecord(currentUser, recordOwner) {
  // 管理员可以编辑所有记录
  if (isAdmin(currentUser.employeeId)) {
    return true
  }
  // 普通鉴定员只能编辑自己的记录
  return currentUser.employeeId === recordOwner.employeeId
}
```

### 2. 检查是否可以访问管理后台

```javascript
function canAccessAdminPanel(employeeId) {
  // 管理员和超级管理员可以访问
  return isAdmin(employeeId)
}
```

### 3. 检查是否可以设置角色

```javascript
function canSetRole(employeeId, targetRole) {
  // 只有超级管理员可以设置角色
  if (!isSuperAdmin(employeeId)) {
    return false
  }
  // 不能设置为超级管理员
  if (targetRole === 'super_admin') {
    return false
  }
  return true
}
```

### 4. 检查是否可以关联牧场

```javascript
function canLinkFarm(employeeId) {
  // 管理员和超级管理员可以关联牧场
  return isAdmin(employeeId)
}
```

## 常见业务场景

### 场景A：新牧场上线

**参与角色：** 管理员或超级管理员

**操作步骤：**
1. 管理员进入"选择牧场"页面
2. 点击"+ 新建牧场"按钮
3. 输入牧场信息（站号YQN005、名称"新希望牧场"、DHI编号DHI005）
4. 点击"创建"
5. 系统保存牧场信息
6. 进入"管理后台" → "牧场匹配"
7. 分别选择鉴定员A、B、C
8. 为每个鉴定员开启"新希望牧场"的访问权限

**结果：**
- 牧场创建成功
- 指定的鉴定员可以看到并选择该牧场
- 其他鉴定员看不到该牧场

### 场景B：鉴定员晋升为管理员

**参与角色：** 仅超级管理员

**操作步骤：**
1. 超级管理员进入"管理后台"
2. 切换到"鉴定员管理"Tab
3. 找到鉴定员"张三/A001"
4. 点击角色选择器（当前显示"普通鉴定员"）
5. 选择"管理员"
6. 系统更新角色

**结果：**
- 张三的角色变为admin
- 张三可以访问管理后台
- 张三可以创建牧场、关联鉴定员
- 张三可以修改/删除所有人的评分记录
- 张三仍然不能修改其他人的角色

### 场景C：数据纠错

**参与角色：** 管理员或超级管理员

**业务背景：**
鉴定员李四评分时，把耳号"CN1234567"误输入为"CN1234566"

**操作步骤：**
1. 管理员进入"评分记录"页面
2. 找到李四的那条错误记录
3. 点击"编辑"按钮（管理员可以看到所有记录的编辑按钮）
4. 修改耳号为正确值"CN1234567"
5. 保存修改

**结果：**
- 记录被成功修正
- 李四看到的耳号是正确的
- （未来）操作日志记录了管理员修改了这条记录

### 场景D：临时工作调度

**参与角色：** 管理员或超级管理员

**业务背景：**
鉴定员王五临时支援"测试牧场"评分工作，完成后需移除权限

**操作步骤：**

**分配权限：**
1. 管理员进入"管理后台" → "牧场匹配"
2. 选择"王五/A003"
3. 打开"测试牧场"的开关
4. 王五立即可以看到并选择"测试牧场"

**移除权限（工作完成后）：**
1. 管理员再次进入"牧场匹配"
2. 选择"王五/A003"
3. 关闭"测试牧场"的开关
4. 王五的牧场列表中不再显示"测试牧场"

**结果：**
- 灵活的权限分配
- 王五在"测试牧场"的评分记录仍然保留
- 管理员可以随时重新开启权限

## 权限边界说明

### ✅ 允许的操作

1. **管理员修改他人评分记录** - 用于纠错
2. **管理员删除他人评分记录** - 用于数据清理
3. **超级管理员设置其他人为管理员** - 扩大管理团队
4. **超级管理员将管理员降级为普通鉴定员** - 权限回收
5. **管理员关联/取消关联任意鉴定员和牧场** - 灵活调度

### ❌ 禁止的操作

1. **普通鉴定员修改他人记录** - 保护数据安全
2. **管理员设置角色** - 只有超级管理员可以
3. **任何人修改超级管理员角色** - 系统保护
4. **任何人将用户设为超级管理员** - 只能系统预设
5. **普通鉴定员访问管理后台** - 权限不足
6. **普通鉴定员创建牧场** - 权限不足
7. **普通鉴定员关联鉴定员到牧场** - 权限不足

## 权限设计原则总结

1. **最小权限原则**：每个角色只拥有完成工作所需的最小权限
2. **权限分离**：评分、管理、系统维护三层分离
3. **安全保护**：超级管理员角色受系统保护
4. **灵活调度**：管理员可以灵活分配鉴定员到牧场
5. **数据质量**：管理员有权纠正错误数据
6. **可追溯性**：所有操作应记录日志（未来功能）
