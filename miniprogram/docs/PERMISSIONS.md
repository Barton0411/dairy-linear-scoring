# 权限管理体系说明

## 一、权限等级

系统设计了三级权限体系：

### 1. 普通鉴定员 (appraiser)

**权限范围：**
- ✅ 登录系统
- ✅ 选择被分配的牧场（仅能看到已关联的牧场）
- ✅ 进行奶牛线性评分
- ✅ 拍摄照片并上传
- ✅ 查看自己的评分记录
- ✅ **修改/删除自己创建的记录**
- ✅ 查看同一牧场其他鉴定员的记录（只读）
- ✅ 导出自己的评分数据

**限制：**
- ❌ 无法创建牧场
- ❌ **无法修改/删除他人的记录**
- ❌ 无法访问管理后台
- ❌ 无法修改权限

### 2. 管理员 (admin)

**权限范围：**
- ✅ 普通鉴定员的所有权限
- ✅ **修改/删除所有人的评分记录**（用于纠错和数据管理）
- ✅ **新建牧场**（输入牧场名称、站号、DHI编号）
- ✅ **关联鉴定员和牧场**（分配鉴定员到指定牧场）
- ✅ **取消关联**（解除鉴定员和牧场的关系）
- ✅ 查看所有牧场列表
- ✅ 导出所有牧场数据
- ✅ 访问管理后台

**限制：**
- ❌ 无法设置其他人的角色（不能提升/降级权限）
- ❌ 无法将自己升级为超级管理员
- ❌ 无法修改超级管理员的任何信息

### 3. 超级管理员 (super_admin)

**权限范围：**
- ✅ 管理员的所有权限
- ✅ **修改/删除所有人的评分记录**（用于纠错和数据管理）
- ✅ **设置鉴定员角色**（普通鉴定员 ↔ 管理员）
- ✅ 管理所有用户权限
- ✅ 完全的系统管理权限

**限制：**
- ❌ 无法修改其他超级管理员的权限
- ❌ 无法将普通用户直接设为超级管理员（超级管理员由系统预设）
- ❌ 自己的角色无法被降级（系统保护）

## 二、权限设计原则

### 2.1 权限分离
- **普通鉴定员**：专注于评分工作，避免误操作
- **管理员**：负责日常管理（牧场创建、人员分配）
- **超级管理员**：负责权限管理和系统维护

### 2.2 最小权限原则
- 每个角色只拥有完成其工作所需的最小权限
- 避免权限过度集中

### 2.3 安全保护
- 超级管理员角色受系统保护，无法被降级
- 防止误操作导致系统无管理员
- 管理员无法提升自己的权限

## 三、评分记录权限详解

### 3.1 为什么管理员可以修改他人记录？

在实际业务场景中，管理员需要修改他人记录的原因包括：

1. **数据纠错**：鉴定员可能输错牛号、胎次等信息，需要管理员帮助修正
2. **补充信息**：评分后发现缺少DHI编号等必要信息，管理员统一补充
3. **质量控制**：发现评分有误时，管理员有权修正以保证数据质量
4. **数据管理**：批量调整、迁移或清理过期数据

### 3.2 权限控制实现

**代码逻辑：**
```javascript
// 在 pages/records/list/list.js 中
const userIsAdmin = isAdmin(this.data.userInfo.employeeId)
const canEdit = userIsAdmin || record.employeeId === this.data.userInfo.employeeId
const canDelete = userIsAdmin || record.employeeId === this.data.userInfo.employeeId
```

**UI显示：**
- 普通鉴定员：只能看到自己记录上的"编辑"和"删除"按钮
- 管理员/超级管理员：所有记录上都显示"编辑"和"删除"按钮

### 3.3 操作日志（未来扩展）

为保证可追溯性，未来应实现操作日志功能：
- 记录谁在什么时间修改了哪条记录
- 记录修改前后的数据对比
- 支持查询修改历史

## 四、权限判断逻辑

### 4.1 角色检查函数

```javascript
// 获取用户角色
getAppraiserRole(employeeId)
// 返回: 'appraiser' | 'admin' | 'super_admin'

// 是否为管理员（包括admin和super_admin）
isAdmin(employeeId)
// 返回: true/false

// 是否为超级管理员
isSuperAdmin(employeeId)
// 返回: true/false
```

### 4.2 功能访问控制

| 功能 | 普通鉴定员 | 管理员 | 超级管理员 |
|------|-----------|--------|-----------|
| 评分 | ✅ | ✅ | ✅ |
| 查看记录 | ✅（仅自己） | ✅（所有） | ✅（所有） |
| 修改记录 | ✅（仅自己） | ✅（所有） | ✅（所有） |
| 删除记录 | ✅（仅自己） | ✅（所有） | ✅（所有） |
| 新建牧场 | ❌ | ✅ | ✅ |
| 关联牧场 | ❌ | ✅ | ✅ |
| 设置角色 | ❌ | ❌ | ✅ |
| 访问管理后台 | ❌ | ✅ | ✅ |

### 4.3 UI显示控制

**设置页面：**
```xml
<!-- 仅管理员和超级管理员可见 -->
<view wx:if="{{isAdmin}}">
  <button bindtap="onOpenAdminPanel">管理后台</button>
</view>
```

**管理后台 - 角色管理Tab：**
```xml
<!-- 仅超级管理员可修改角色 -->
<picker wx:if="{{isSuperAdmin && item.role !== 'super_admin'}}" ...>
  <!-- 角色选择器 -->
</picker>
```

**牧场选择页：**
```xml
<!-- 仅管理员可新建牧场 -->
<button wx:if="{{isAdmin}}" bindtap="onCreateFarm">+ 新建牧场</button>
```

## 五、权限变更流程

### 5.1 提升权限（普通鉴定员 → 管理员）

**操作者：** 仅超级管理员

**步骤：**
1. 进入管理后台
2. 选择"鉴定员管理"Tab
3. 找到目标鉴定员
4. 点击角色选择器
5. 选择"管理员"
6. 系统更新角色并保存

**限制：**
- 不能修改超级管理员的角色
- 不能将用户直接提升为超级管理员

### 5.2 降低权限（管理员 → 普通鉴定员）

**操作者：** 仅超级管理员

**步骤：** 同上，选择"普通鉴定员"

**影响：**
- 失去新建牧场权限
- 失去关联鉴定员权限
- 无法访问管理后台
- 保留自己的评分记录和数据

### 5.3 关联牧场

**操作者：** 管理员或超级管理员

**步骤：**
1. 进入管理后台
2. 选择"牧场匹配"Tab
3. 选择鉴定员
4. 开启对应牧场的开关
5. 系统建立关联关系

**效果：**
- 该鉴定员可在牧场列表中看到该牧场
- 可选择该牧场进行评分工作

## 七、常见问题

### Q1: 如何设置第一个超级管理员？
A: 超级管理员在系统初始化时预设（employeeId: 10075345），无法通过界面创建。如需添加新的超级管理员，需修改数据库或mock数据。

### Q2: 管理员可以自己提升自己的权限吗？
A: 不可以。角色修改功能仅对超级管理员开放，管理员无法访问角色设置功能。

### Q3: 如果所有超级管理员都被误删怎么办？
A: 超级管理员的角色受系统保护，无法通过界面删除或降级。如果数据库出现问题，需通过数据库脚本恢复。

### Q4: 鉴定员可以看到其他牧场的数据吗？
A: 普通鉴定员只能看到自己被分配的牧场。管理员和超级管理员可以看到所有牧场。

### Q5: 评分记录的修改权限如何控制？
A:
- **普通鉴定员**：只能修改/删除自己创建的评分记录
- **管理员和超级管理员**：可以修改/删除所有人的评分记录（用于纠错和数据管理）
- 所有修改操作都会记录操作日志，保证可追溯性

## 八、未来扩展

如果需要更细粒度的权限控制，可以考虑：

1. **区域管理员**：管理特定区域的牧场和鉴定员
2. **只读管理员**：可以查看所有数据但不能修改
3. **数据分析员**：只能导出和分析数据，不能评分
4. **认证审核员**：专门负责审核鉴定员的认证申请

这些角色可以通过扩展 `role` 字段或使用权限位图来实现。
